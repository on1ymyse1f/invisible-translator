# Browser extension privacy boundary

- The extension is injected only by seven fixed HTTPS origins: `chatgpt.com`, `chat.openai.com`, `claude.ai`, `x.com`, `twitter.com`, `youtube.com`, and `www.youtube.com`. Ports, URL credentials, and look-alike subdomains are rejected. It has no `<all_urls>` permission and no optional host permission.
- It performs no `fetch`, `XMLHttpRequest`, WebSocket, telemetry, crash reporting, or analytics. It stores no API key and declares no remote code.
- The page text sent for an explicitly enabled translation is limited to 64 segments / 256 KiB UTF-8 per request and response and travels only through browser native messaging to the local macOS app. Content and worker both enforce the request limit; worker and content both reject malformed responses.
- Automatic page/subtitle translation is disabled by default. Startup sends one body-free settings query containing only protocol version and the exact canonical origin; the worker binds it to the sender tab, top frame, document ID and navigation generation before asking the short-lived native host. Only a valid response for that same origin can reach that document. A webpage cannot provide settings or include page text in this bootstrap.
- Mutation observers are attached only to a supported site's selected content/caption container, never `document` or `body`. A known message/content selector must match or scanning fails closed. Draft editors, text boxes, forms, controls, navigation and code are excluded from automatic and hover translation. Hover translation uses a dwell timer and does not capture screenshots, clipboard data, keystrokes, URLs outside the active supported site, or browser history.
- The worker binds each request to tab ID, frame ID, document ID, origin, kind, and navigation generation. Results must match its version, request ID, origin, and kind; navigation, expiry, tab closure, malformed replies, and one-shot native-host failure discard pending records. It uses `sendNativeMessage`, not a persistent native port, so the extension does not keep a helper resident while idle.
- The native app is the policy enforcement point: it verifies the peer UID, sender origin, fixed domain allow-list, and a default-empty per-domain user authorization before calling Apple local translation. It records no source text and never silently falls back to a cloud provider. The embedded helper must be signed and installed as `com.on1ymyse1f.InvisibleTranslator`; for local testing, its manifest permits only the exact Chromium extension ID explicitly supplied by the user. The repository does not assign or claim a production/store extension ID.
- Removing the extension stops all browser-side processing. The extension owns no model, cache, or user data outside normal browser extension storage for future non-content settings.
- The strict helper/App IPC chain and fail-closed installer are implemented and locally testable. A verified production/store extension ID binding, Developer ID signing/notarization, and a real Chrome installation/runtime test remain external release blockers; a user-supplied local ID does not satisfy those gates.
